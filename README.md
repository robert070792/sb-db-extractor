# 유승빈 DB추출기 v3.22 시험판

네이버 쇼핑 상품을 수집하고, 실제 스토어 주소와 상품번호를 검증한 뒤 회사 가망·사업자정보를 확인해 010 후보를 CSV로 저장하는 Chrome 확장 프로그램입니다.

## 고정한 실행 방식

1. 키워드가 바뀌면 실제 검색창에 입력하고 돋보기 버튼을 클릭합니다. 최대 20개 키워드를 순차 처리합니다.
2. 지정한 페이지의 일반·광고 상품과 원부 판매처를 수집합니다. 페이지 이동은 실제 숫자 버튼을 클릭하며 URL을 직접 바꾸지 않습니다.
3. 실제 주소 근거와 판매자·채널·상품번호를 대조합니다. 식별 충돌은 보류하며, 주소 미확인 업체도 번호 기반 조회 대상으로 보존합니다.
4. 회사 가망을 확인한 뒤 온전한 010이 있는 회사 캐시를 우선 사용합니다. 번호가 없거나 일반전화·가려진 번호이면 새로 조회합니다. 스토어 주소가 있으면 HTTPS `/store/seller-info`, 없으면 v2.9/v3.5의 판매자번호+쇼핑상품번호 `/extension/business-info`를 사용합니다.
5. 제공된 연락처 중 010을 찾고, 미확보 업체도 보류 CSV에 남깁니다. 영업 CSV는 기존 16열을 유지합니다.

## 설치·업데이트

`설치안내.txt`를 먼저 확인하세요. 기존 사용자는 기존 확장을 삭제하지 말고 **기존 확장 폴더에 새 파일을 덮어쓴 뒤 chrome://extensions에서 새로고침**하세요. 같은 Chrome 프로필·확장 ID를 유지해야 기존 조회 이력을 승계합니다.

다른 폴더에서 새 확장으로 추가하거나 Chrome 프로필을 바꾸면 이전 저장소가 자동 이전되지 않습니다. 진행 중인 작업은 중단하고 결과 CSV·전체 진단을 먼저 보관하세요. 업데이트 후 이전 결과를 보관하고 작업 초기화 뒤 새로 시작하세요. 이전 요청 이력은 보관하지만 새 작업의 필요한 조회를 차단하지 않습니다. 이어하기는 같은 작업으로 취급합니다.

## 수정 내용

`변경사항_v3.22.md`에 정리했습니다. 번호 기반 조회를 복원하고, 불완전한 캐시를 신규 조회로 넘깁니다. 페이지 전환은 실제 숫자 버튼과 일반상품 변화 또는 새 검색응답·페이지 메타의 일치로 확인합니다. 원부 판별기 v2.4의 판매처 상품번호 검증 파서를 통합했습니다. 특이사항은 검색광고, 원부상품을 표시하며 일반상품 분류 문구는 비웁니다. 기존 사업자·전화번호 중복 경고는 유지합니다.

실제 스토어 ID가 전혀 제공되지 않는 상품의 주소는 추측하지 않습니다. `/main/products/번호`는 원본 관측값으로만 보존하고 검증된 최종 링크로 내보내지 않습니다.

## 검증과 한계

`검증결과_v3.22.md`에 실제 실행한 검사와 미검증 범위를 구분했습니다. 두 키워드 × 두 페이지의 DOM 기반 전체 연결 시험을 포함한 자동 검사는 오프라인 모의 서버로 수행했습니다. 실제 네이버·회사 로그인 서버, 유료조회, 사용자 PC의 Chrome 확장 실행 성공을 보증하는 결과는 아닙니다.

부재·거절의 3일 경과 처리는 회사 서버가 반환하는 상태에 의존합니다. 회사 프로그램의 전화걸기·TM앱·통화시간·통화요약 기능을 이번 추출기 UI에 새로 통합한 것은 아닙니다. 기존 통화기록 CSV 열은 유지합니다.

관측한 상품 수, 식별하지 못한 후보 수, 업체 통합 수는 다른 지표입니다. 화면에 로드되지 않아 관측하지 못한 카드까지 정확히 셌다고 표시하지 않습니다.

## 개발·테스트

Node.js 20 이상과 Python 3을 사용합니다. 확장 프로그램 실행 자체에는 npm 의존성이 없습니다. jsdom은 개발 테스트에만 사용합니다.

```bash
npm ci
npm test
python3 tools/build_release.py
```

기존 테스트 9개 파일의 목적을 유지하고 URL 우선 이동을 기대하던 검사는 실제 숫자 버튼 클릭 요구로 갱신했습니다. 회귀검사는 `tests/test_v321_integrity.cjs`, `tests/test_v321_dom.cjs`, `tests/test_v322_workflow.cjs`에 있습니다. 실제 인증 쿠키나 사내 연락처 없이 모의 응답으로 검사합니다.

번호 조회 서버의 현재 운영 상태는 미검증입니다. 클라우드에서 문서 주소 접근 시 403 Domain forbidden을 받아 실제 조회 요청은 실행하지 않았습니다. 이는 운영 서버 자체의 장애로 확정한 결과가 아닙니다.
