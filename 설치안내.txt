유승빈 DB추출기 v3.31 설치 및 업데이트

[기존 사용자: 조회 이력을 유지하는 업데이트]
1. 실행 중인 추출을 중단하고, 영업 CSV·보류 CSV·전체 진단 JSON을 저장합니다.
2. 사용 중인 기존 확장 폴더와 원본 ZIP을 백업합니다. 기존 확장 프로그램은 삭제하지 않습니다.
3. 새 ZIP을 임시 폴더에 풉니다. manifest.json이 들어 있는 폴더의 내용(src, icons, manifest.json 등)을 기존 확장 프로그램이 사용하는 폴더에 덮어씁니다.
4. chrome://extensions에서 기존 DB추출기의 새로고침 버튼을 누릅니다. 같은 확장 ID인지 확인합니다.
5. 네이버 쇼핑 탭을 F5로 새로고침합니다. 회사 어드민·네이버 로그인을 유지합니다.
6. 패널의 버전이 v3.31인지 확인합니다. v3.30에서 재클릭 전 위치 검사로 중단된 작업은 초기화하지 않고 [이어하기]로 시험할 수 있습니다. 새 작업은 결과 백업 후 초기화하고 시작하세요.
   v3.21 이하에서 업데이트한다면 번호 조회 서버(smartwin.iptime.org) 접근 권한이 추가됩니다. Chrome에서 새 권한 확인이 나오면 해당 권한을 허용하고 확장을 활성화하세요.
7. 검색창·돋보기·실제 2페이지 숫자 버튼 동작과 영업/보류/수집검증 CSV를 확인하고 전체 진단 JSON을 보관합니다.

[처음 설치]
압축을 푼 뒤 chrome://extensions에서 개발자 모드를 켜고 [압축해제된 확장 프로그램 로드]로 manifest.json이 있는 폴더를 선택합니다.

[조회 이력]
- v3.26은 같은 Chrome 프로필과 확장 ID에 남아 있는 v3.19 요청 이력을 승계합니다.
- 작업 초기화는 결과를 비우고 과금 가능 요청 이력은 유지합니다.
- 다른 폴더에 새 확장으로 추가하거나 기존 확장을 제거하면 이전 저장소가 자동 이전되지 않습니다.
- 예전에 이미 지워진 조회 이력은 복원할 수 없습니다.
- 같은 작업에서는 전송 후 실패·응답 불명 요청을 자동 반복하지 않습니다. 새 작업에서는 필요한 조회를 다시 실행하며 이전 작업의 요청 이력으로 막지 않습니다.
- v3.26에서 로그인 실패 등 실제 미전송이 확인된 오류는 로그인 복구 후 새 추출로 다시 처리할 수 있습니다.

[확인 필요]
이 파일은 실제 네이버·사내 서버에서 전체 기능 검증을 마친 운영 완성판이 아닙니다. 자동 회귀검사와 DOM 모의 연결 시험을 마친 수정판입니다.
회사 사업자조회기의 별도 통화·TM 기능은 기존 회사 프로그램을 계속 사용합니다.

[결과 확인]
- 최신 주소 기반 조회와 번호 기반 조회 성공 건수는 별도로 표시됩니다.
- 회사 캐시에 일반전화·번호 없음·010 일부 가림이면 신규 조회합니다.
- 특이사항: 검색광고 / 원부상품 / 검색광고, 원부상품. 일반상품 분류 문구는 빈칸입니다. 기존 중복 경고는 유지합니다.
- 원부 판별기 별도 설치는 필요 없습니다. 판별 파서를 추출기에 포함했습니다.
- 실패 시 [전체 진단 JSON]을 저장하면 페이지 전환 전후 상품번호·검색응답 식별자·조회 경로를 확인할 수 있습니다.

[v3.26 추가 확인]
- 현재 3페이지에서 2~5페이지를 지정해도 실제 숫자 버튼으로 2페이지부터 수집합니다.
- 같은 상품이 여러 페이지에 나와도 페이지별 관측 수는 보존하고 최종 상품·업체는 중복 제거합니다.
- 사용자가 직접 연 상품 페이지에서 판매자·상품번호와 실제 주소를 확인할 수 있으면 연결을 기억합니다. 업데이트 전에 열었던 페이지는 다시 새로고침해야 합니다. 자동으로 광고를 클릭하거나 모든 주소를 알아내는 기능은 아닙니다.
- 최신화 후에도 일반전화만 제공되는 업체는 010 미확보 보류가 맞습니다.
- 번호 조회 서버 HTTP 404는 서버 지원/응답 확인이 필요한 별도 문제입니다. 구형 조회기 재설치만으로 해결된다고 보증하지 않습니다.

[v3.26 수정]
- 추적 링크 형태인 원부상품도 원부 식별정보가 일치하면 판매처 조회 대상으로 처리합니다.
- 검색응답 ID 변경만으로 2페이지 성공 처리하지 않습니다. 복구 시 이전 페이지 로딩 완료 후 비교 기준을 새로 잡습니다.
- 현재 번호 앞의 ‘현재 페이지’ 문구를 제외하고 숫자를 읽습니다.
- 미식별 후보의 페이지별 관측 합계와 고유 후보 수를 구분합니다. 원부 대표·판매상품·업체 수는 서로 다른 숫자입니다.
- v3.23 실행 결과와 진단을 먼저 저장한 뒤 초기화하고 새 작업을 시작하세요.
- 번호 조회 HTTP 404 및 최신 조회 서버의 실패 응답은 별도 문제이며 이번 버전에서 복구를 보증하지 않습니다.

[v3.26 페이지 확인과 스크롤]
- 실제 목표 페이지 상품 갱신 확인 후 맨 위부터 아래로 수집합니다. 페이지 숫자만 바뀐 상태는 성공으로 보지 않습니다.
- 실패 후 자동 1→2페이지 왕복과 자동 재스크롤을 제거했습니다. HTTP 418 등 검색 오류 시 추가 클릭·수집 스크롤 없이 오류 코드를 표시합니다.
- 기존 수집 상품을 보존하고 해당 페이지에서 기다립니다. 정상 상품이 표시된 뒤 [이어하기]를 누르세요. 계속 요청이 실패하면 자동 진행하지 않습니다.
- v3.25에서 남은 수집 작업은 업데이트 후 이어하기로 재개할 수 있습니다. 새 시험은 결과 백업 후 [초기화]하세요.
- 통합 진단에 요청 범위·다음 수집 페이지·검색 요청 관측·HTTP 오류가 포함됩니다.

[v3.27 켜짐/꺼짐 비교]
- 리뷰수 필터 바로 아래 [네이버 원부 추가 조회: 꺼짐] 버튼을 누르면 켜짐/꺼짐이 전환됩니다.
- 최초 사용·초기화 후 기본값은 꺼짐입니다. 꺼짐이면 화면 정보만 수집하고 원부 판매처 추가 요청은 0회입니다. 검색과 페이지 이동, 회사 사업자조회는 계속 작동합니다.
- 결과·전체 진단 저장 → 초기화 → 꺼짐으로 키워드 1개·1~3페이지 실행 → 전체 진단 저장 → 초기화 → 켜짐으로 같은 조건 실행 → 전체 진단 저장 순서로 비교하세요.
- 실행 중이거나 이어갈 작업이 있으면 설정을 잠급니다. 이어하기는 기존 작업 설정을 유지합니다. v3.26 이하 작업을 이어가면 기존 조회 켜짐을 유지하므로 꺼짐 시험은 초기화 후 시작하세요.
- 묶음상품 제외와 원부 조회 끄기는 다릅니다. 묶음상품 필터는 비교 중 같은 값으로 유지하세요.
- 버튼 아래의 원부 요청 횟수와 통합 JSON을 확인하세요. ‘전송 여부 미확인’ 또는 ‘이전 버전 미집계’가 있으면 전체 요청 0회로 판단하지 않습니다.
- 원부 조회를 끄면 화면에 없는 연결 판매처는 추가 수집하지 않습니다. HTTP 418 해소 여부는 실제 비교가 필요합니다.

[v3.28 화면에 보이는 페이지 버튼 클릭]
- 페이지 버튼을 화면 중앙으로 이동 → 0.65초 대기 → 화면 안·가림 없음·위치 유지 확인 → 실제 버튼 클릭 순서입니다.
- 네이버 쇼핑 탭을 화면에 표시하세요. 추출기 창이 페이지 버튼을 가리면 창을 옮기거나 접은 뒤 [이어하기]를 누르세요.
- 클릭 후 목표 페이지 상품이 실제로 갱신되면 맨 위부터 수집합니다. HTTP 418이면 기존과 같이 대기합니다.
- 새 시험은 기존 결과를 보관한 뒤 초기화하고, 원부 추가 조회 꺼짐·키워드 1개·1~3페이지로 시작하세요.
- 보이는 버튼 클릭도 브라우저 스크립트 클릭입니다. 사람의 마우스 입력과 동일하지 않으며 HTTP 418 해소를 보증하지 않습니다.

[v3.29 시작 페이지 이동 보정]
- v3.28에서 버튼 위치 검사 한 번으로 시작 페이지 이동이 막히던 동작을 보완했습니다.
- 버튼 위치가 화면 밖이거나 움직이면 클릭 전에 최대 두 번 더 중앙 위치를 맞춥니다. 가려진 버튼은 클릭하지 않습니다.
- 화면에 보이는 버튼 영역을 확인합니다. 버튼 테두리 일부가 화면을 벗어났다는 이유만으로 중단하지 않습니다.
- 위치 확인 실패 사유를 화면에 그대로 표시하고 통합 진단에 좌표·화면 크기·보정 시도를 저장합니다.
- 결과를 보관한 뒤 초기화하고, 현재 3페이지에서 1~3페이지 자동 추출을 시험하세요. 실제 환경에서의 성공은 추가 확인이 필요합니다.
- 이 버전은 버튼 위치 문제에 대한 보완입니다. HTTP 418, 사업자조회 404 및 서버 응답 실패의 해결을 보증하지 않습니다.

[v3.30 페이지 이동 후 새로고침]
- 새 가격비교 자동 추출은 숫자 버튼 이동 뒤 현재 탭을 1회 새로고침하고 실제 페이지와 상품을 확인한 다음 스크롤합니다.
- HTTP 418 등으로 주소가 이전 페이지에 남았다면 새로고침 후 이전 페이지로 돌아갈 수 있습니다. 이 경우 실제 목표 숫자 버튼을 1회 다시 누르고 확인합니다.
- 목표 페이지별 새로고침 최대 1회, 복원 후 재클릭 최대 1회입니다. 계속 실패하면 기존 상품을 보존하고 기다립니다.
- 이전 버전 작업을 그대로 이어가면 이전 동작을 유지합니다. 결과 저장 → 초기화 → 원부 추가 조회 꺼짐 → 1~3페이지 전체 자동 추출로 새 시험을 시작하세요.
- 새로고침 중 백그라운드 작업이 종료되면 [이어하기]로 저장 상태를 복원합니다. 전송 여부가 불명확한 새로고침/클릭은 반복하지 않습니다.
- pageReloads 및 collection.reloadPlan에 새로고침·복원 페이지·재클릭·검증 상태가 기록됩니다.
- 실제 HTTP 418 해소와 별도 사업자조회 서버 오류 해결은 보증하지 않습니다.

[v3.31 새로고침 후 하단 로딩]
- 새로고침 후 이전 페이지로 돌아온 경우, 아래로 스크롤하면서 추가 로딩을 기다린 뒤 목표 버튼을 준비합니다.
- 하단에서 높이·스크롤 위치·상품 목록이 약 2초간 안정되어야 재클릭합니다. 최대 80단계 안에 안정되지 않으면 클릭하지 않고 기다립니다.
- 복원된 이전 페이지의 준비용 스크롤은 목표 페이지 수집으로 집계하지 않습니다.
- 버튼 위치 검사에서 클릭하지 않은 것이 확인되면 재클릭 기회를 소모하지 않습니다. 발신 여부가 불명확하거나 실제 클릭한 경우에는 자동 반복하지 않습니다.
- v3.30의 BUTTON_OUTSIDE/BUTTON_MOVED 기록으로 실제 클릭 전 거절이 확인되는 작업도 이어하기로 복원합니다. 기존 상품과 새로고침 횟수는 보존합니다.
- 진단 pageReloads/collection.reloadPlan의 positioning에서 높이·상품 개수·하단 안정 상태를 확인할 수 있습니다.
